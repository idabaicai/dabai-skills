# 英文研报翻译 → 中英对照 HTML

把英文研究报告（券商研报、行业报告、公司分析等）翻译成专业的简体中文，输出一份中英对照的 HTML 文件，供用户直接在浏览器中阅读。

## 工作流程

### 1. 获取原文

- **PDF 文件**：用 Read 工具直接读取。超过 10 页的 PDF 必须用 `pages` 参数分段读取（每次最多 20 页）。先读第 1 段确认内容结构，再按需继续。
- **网页链接**：用 WebFetch 抓取。如果 WebFetch 拿到的内容残缺（付费墙、JS 渲染），告知用户并请其提供 PDF 或粘贴原文。
- **粘贴文本**：直接使用。

读取时留意报告的结构：标题、作者/机构、日期、评级/目标价摘要框、章节标题、图表、数据表格、脚注和免责声明。这些结构要在 HTML 中还原。

### 2. 翻译

逐段翻译，一个英文段落对应一个中文段落，不合并、不省略。翻译质量标准：

- **文风**：中文券商研报的书面语——简洁、专业、判断句式（"我们认为……"、"预计……"、"维持买入评级"）。避免翻译腔（如"根据我们的观点"应作"我们认为"）。
- **术语**：以中文为主，专业术语**首次出现**时在括号内标注英文原文或通行缩写，之后直接用中文或通行缩写。例如：首次写"息税折旧摊销前利润（EBITDA）"，之后写"EBITDA"；首次写"市场一致预期（consensus）"，之后写"一致预期"。
- **不翻译的内容**：公司名（可加中文通称，如 "NVIDIA（英伟达）"）、股票代码、人名、指数名缩写、产品型号、数据本身。
- **数字与单位**：务必换算准确——billion 是"十亿"（或换算成"XX 亿"），million 是"百万"。基点（bps）、百分点、同比（YoY）/环比（QoQ）按中文习惯表达。这是研报翻译最容易出错、后果最严重的地方，每个数字都要核对。
- **评级词**：Buy=买入，Overweight=增持/超配，Hold/Neutral=持有/中性，Underweight=减持/低配，Sell=卖出，Price Target (PT)=目标价。
- **图表**：无法提取的图片用占位块表示，翻译其标题和图注，如：【图 3：季度营收走势（Quarterly Revenue Trend）】。数据表格要还原成 HTML 表格，表头翻译，数字原样保留。
- **免责声明**：篇幅长的合规样板文字（disclaimer/disclosure）翻译后放进可折叠区块，不占正文空间；如篇幅极长可只翻译要点并注明"以下为节选"。

### 3. 生成 HTML

以 `assets/template.html` 为底稿（先 Read 它），按其中的注释填入内容。核心结构是"对照块"：每个翻译单元里英文原文在上（灰色小字），中文译文在下（正文主体）。标题也做对照（英文小字 + 中文大字）。

- **列表逐条对照**：列表用 `<ul class="pair-list">`（有序列表用 `<ol class="pair-list">`），每个 `<li>` 内英文 `<span class="en">` 一行、中文 `<span class="zh">` 一行。不要把整个列表的英文和中文分成两个 ul——条目一多，读者就没法逐条对照了。有序列表的序号由 CSS 计数器自动生成，不要在文字里手写编号。
- **语言切换**：模板右上角内置「中文 / 对照 / EN」三态切换按钮（选择记忆在 localStorage），由 body 上的 `mode-zh` / `mode-en` class 控制显隐。切换能全局生效依赖一条纪律：**所有英文内容放在 `class="en"` 的元素里，所有中文放在 `class="zh"` 里**——段落、标题、列表、图注、表格 caption 都如此，不能有裸露在这两个 class 之外的成段单语内容，否则切换后会漏显或多显。表格单元格里语言无关的数字不用标；表头等短文本可用"中文（English）"混排，三种模式下都可见，是可接受的例外。纯文字表格加 `class="text"` 获得左对齐、可换行样式。
- 输出文件保存在源文件同目录（URL 来源则存当前工作目录），文件名用报告主题命名，如 `nvidia-q2-2026-点评-中英对照.html`。
- 全部样式内联在文件内，不引用外部资源，保证离线可读、可直接转发。
- 生成后用 `open <文件>` 在浏览器中打开，并告知用户文件路径。

### 长报告的处理

超过约 15 页的报告不要试图一次性读完再翻译——分批进行：读一批页 → 翻译 → 追加写入 HTML → 读下一批。这样即使中途中断也有可用的部分成果。开始前告知用户报告较长、预计分几批完成。

## 质量自检

交付前检查：

1. 段落数对得上——原文的每个实质段落在 HTML 里都有对照块，没有整段漏译。
2. 抽查 3-5 个关键数字（营收、目标价、增长率），确认译文与原文一致、单位换算无误。
3. 标题层级、表格、列表在 HTML 中结构正确，浏览器打开无乱码（UTF-8）。
